# Founder — پیدا کردن تصویر و خواندن متن روی ریموت

همه‌چیز در یک فایل است: `founder.py`. آن را کنار پروژه بگذارید یا پوشه‌ی Founder را به `sys.path` اضافه کنید.

```python
from founder import Remote, Screen

remote = Remote("XBOX")              # همان ریموت xbrp (pipe: \\.\pipe\xbrp-XBOX)
scr = Screen(remote)                 # تصویرها از Founder\Templates

with scr.frozen():                   # همه‌ی بررسی‌ها روی یک فریم
    if scr.find("Cancel", 570, 400, 135, 135):
        remote.press("a")
    elif scr.contains("Home", 140, 47, 80, 27):
        ...
```

## مختصات: نسبت به تصویر ریموت

همه‌ی عددها نسبت به تصویر خود استریم هستند: 1280x720، گوشه‌ی بالا-چپ تصویر = 0,0.
جا و اندازه‌ی پنجره‌ی ریموت روی صفحه‌ی کامپیوتر هیچ اثری ندارد، چون تصویر مستقیم از ریموت گرفته می‌شود.

برای گرفتن عددها:

```
python pick.py XBOX
```

تصویر ریموت در اندازه‌ی واقعی باز می‌شود. با موس ناحیه بکشید تا x, y, w, h و متن آن در ترمینال بیاید و در کلیپ‌بورد کپی شود.
کلید S ناحیه را به‌عنوان تصویر نمونه ذخیره می‌کند و F امتحان می‌کند پیدا می‌شود یا نه.
Space فریم تازه می‌گیرد و L حالت زنده را روشن می‌کند.

## توابع

| تابع | خروجی | جای قدیمی |
|---|---|---|
| `find(name, x, y, w, h, threshold=0.8)` | `Match`؛ در `if` درست/غلط است و `ok, x, y = ...` هم کار می‌کند | `Pfind` و `Pfind2` |
| `find_all(name, ...)` | لیست همه‌ی جاهای پیدا شده | جدید |
| `find_any([n1, n2], ...)` | بهترین مورد؛ `m.name` می‌گوید کدام | جدید |
| `wait(name, ..., timeout=10)` / `wait_gone(...)` | صبر تا ظاهر یا ناپدید شدن | جدید |
| `read(x, y, w, h, whitelist=None)` | متن | `ReadText` |
| `read_number(...)` | عدد صحیح یا `None` (مثلاً `15,750` → `15750`) | `re.sub(r'\D','',ReadText(...))` |
| `see("Cancel", ..., text=None, threshold=0.9, fuzzy=0.95)` | اول تصویر، اگر نبود متن؛ `m.by` می‌گوید کدام. `text=False` = فقط تصویر | جدید |
| `wait_see(...)` | صبر تا تصویر یا متن بیاید | جدید |
| `act_until(Up, lambda s: s.see(...))` | دکمه را تکرار کن تا شرط درست شود | جدید |
| `until(...)` / `wait_text(...)` / `wait_change(...)` / `wait_stable(...)` | صبرهای هوشمند | جدید |
| `detect([("Home", "see:Home"), ...])` | تشخیص صفحه روی یک فریم | جدید |
| `is_blank(...)` | صفحه‌ی سیاه یا یکدست | جدید |
| `contains("Home", ...)` | درست/غلط، متن دقیق (پیش‌فرض `fuzzy=1.0`) | `'Home' in ReadText(...)` |
| `find_text("Market")` | جای یک کلمه روی صفحه، بدون تصویر نمونه | جدید |
| `read_all(...)` | همه‌ی خط‌ها با جایشان | جدید |
| `pixel(x, y)` / `color_near(...)` / `changed(...)` | رنگ و تغییر ناحیه | جدید |
| `save_template(name, x, y, w, h)` | ذخیره‌ی تکه‌ای از فریم به‌عنوان تصویر نمونه | جدید |

اگر ناحیه ندهید، کل صفحه گشته می‌شود. ولی ناحیه‌ی کوچک بسیار سریع‌تر است.
`Pfind`، `Pfind2` و `ReadText` با همان ورودی و خروجی قبلی هم هستند.
پس کد قدیمی با عوض کردن `self.` به `scr.` کار می‌کند.

## کد قدیمی Transfer با مختصات 1920x1080

تصویرهای پروژه‌ی Transfer در `Templates\1080` کپی شده‌اند. استریم جدید 1280x720 است.
با `ref` مختصات و تصویرهای قدیمی خودکار کوچک می‌شوند و خروجی هم با مختصات قدیمی برمی‌گردد:

```python
old = Screen(remote, templates=r"Templates\1080", ref=(1920, 1080))
ok, x, y = old.Pfind2("UTCoin", 1400, 60, 200, 50)
```

این برای شروع خوب است. ولی تصویر کوچک‌شده کمی تار می‌شود. بهتر است تصویرهای مهم را دوباره از خود استریم بگیرید:

```python
scr.grab()
scr.save_template("Cancel", 600, 433, 86, 24)   # Templates\Cancel.png در اندازه‌ی واقعی 720
```

## چرا این روش بهتر است

- **OCR ویندوز به‌جای Tesseract.** هر خواندن ۱ تا ۱۲ میلی‌ثانیه است، نه ۹۰. دقیق‌تر هم بود: `Bid` را درست خواند و Tesseract نوشت `Bia`.
  اگر OCR ویندوز نباشد، خودکار Tesseract استفاده می‌شود: `Screen(..., ocr="tesseract")`.
- **یک فریم برای چند بررسی.** در کد قدیمی هر `ReadText` فریم جدا می‌گرفت. با `frozen()` همه روی یک فریم انجام می‌شوند.
  بیرون از `frozen()` فریم بعد از هر دکمه، یا اگر از ۰٫۳ ثانیه قدیمی‌تر باشد، خودکار عوض می‌شود.
- **بدون قفل سراسری.** قفل Tesseract در کد قدیمی همه‌ی ربات‌ها را پشت هم نگه می‌داشت. حالا هر ربات `Screen` خودش را دارد.
- **ناحیه‌ی بیرون از صفحه خطا نمی‌دهد.** بریده می‌شود.
- **تصویر نمونه دقیقاً از استریم.** `save_template` پیکسل‌های خود استریم را ذخیره می‌کند، بدون پنل ریموت و بزرگ‌نمایی پنجره.

## منبع تصویر

- `Remote("XBOX")` با دستور `snap` ریموت فریم می‌گیرد. این دستور روی همه‌ی ۶۰ فریم استریم کار می‌کند، حتی اگر پنجره فقط ۵ فریم نقاشی کند.
- `FileSource("shots/*.png")` برای تست با عکس‌های ذخیره‌شده.
- `ArraySource(frame)` یا `scr.set_frame(frame)` اگر فریم را از جای دیگری دارید.

## تغییرهای ۲۰۲۶-۱۰-۰۶ تا ۱۰-۰۹
- `read_number`: اگر ناحیه چند ردیف عدد زیر هم داشته باشد، لیست برمی‌گرداند (`[64, 63, 63, ...]`)؛ اگر OCR ویندوز عدد ندید، Tesseract امتحان می‌شود.
- `see("ANY (2)", ...)`: برای متن، شماره‌ی تکراری ویندوز حذف می‌شود ("ANY")؛ برای تصویر همان اسم کامل. فقط تصویر: `find(...)`.
- با `Remote(...)`: هر `see/find/read/...` قبل از کار وضعیت ربات و ریموت را چک می‌کند (Pause / Stop / اتصال دوباره) و یک خط در لاگ پنل می‌نویسد؛ اگر تصویر نرسید (`no picture within 3 s`) تا ۳ بار با چک سلامت دوباره می‌گیرد.
- با `FileSource` (تست) هیچ‌کدام فعال نیست؛ `python test_founder.py` باید ۲۱ OK بدهد.

## تنظیمات بالای founder.py

| اسم | مقدار | کار |

| `MAX_AGE` | 0.3 | فریم تا این‌قدر ثانیه دوباره استفاده می‌شود. بعد از هر دکمه همیشه فریم تازه گرفته می‌شود |

| `OCR_CACHE` | 512 | نتیجه‌ی OCR برای ناحیه‌ای که پیکسل‌هایش عوض نشده دوباره حساب نمی‌شود |

## یادداشت‌ها (۲۰۲۶-۱۰)

- **رقم‌ها در see.** با حد قدیمی ۰٫۸، «25 Xbox Seri» به‌جای «27 XBOX Ser» قبول می‌شد. حد متن به ۰٫۹۵ رسید. برای متن‌هایی که فقط یک رقم فرق دارند `fuzzy=1.0` بدهید.
- **تصویر نمونه باید از ناحیه کوچک‌تر باشد.** اگر عکس از ناحیه بزرگ‌تر باشد، see فقط متن را می‌خواند. ناحیه را از هر طرف حدود ۲۰ پیکسل بزرگ‌تر از عکس بگیرید.
- **Play.py تصویرها را از `Screenshot\Shots` می‌گیرد.** این عکس‌ها با RemoteShot از پنجره‌ی 1280x720 گرفته شده‌اند و با نمایشگر ۱۰۰٪ با استریم یک‌به‌یک یکی هستند.
- **مصرف.** با کش OCR، فاصله‌ی ۰٫۲۵ و استفاده‌ی دوباره از فریم، روی عکس ذخیره‌شده تعداد snap در ۳ ثانیه صبر از ۲۱ به ۱۲ و CPU پایتون از ۳۴۴ به ۱۷۲ میلی‌ثانیه رسید. پشتیبان نسخه‌ی قبل: `Play\Backupefore-perf-*`.
- **GPU.** OCR، جستجوی تصویر و خواندن عکس در پایتون GPU مصرف نمی‌کنند. در اندازه‌گیری، بیشتر GPU مال VS Code و dwm بود. برای دیدن مصرف هر برنامه وقتی ربات کار می‌کند: `powershell -ExecutionPolicy Bypass -File gpu_watch.ps1` (فقط شمارنده‌های ویندوز را می‌خواند، به ریموت دست نمی‌زند).
- **بزرگ‌ترین هزینه‌ی باقی‌مانده.** هر snap در ریموت هر پیکسل را جدا تبدیل و PNG فشرده می‌کند (`savePNG` در pad.go). راه حل: حافظه‌ی مشترک در کد Go (انجام نشده).
- **Minimize.** ربات با پنجره‌ی Minimize هم کار می‌کند، چون ریموت هر فریم را قبل از چک Minimize به snap می‌دهد و فقط نقاشی را رد می‌کند. پنل هم با پنجره مخفی می‌شود.
- **خطای «no picture within 3 s».** یعنی خود استریم قطع بوده (در xbrp.log دنبال `skipped packets` و `Session ended` بگردید)، نه خطای Founder.
- **پنجره‌ی Interactive.** بعد از تغییر founder.py یا xbox.py آن را ری‌استارت کنید. پایتون ماژول را فقط یک بار می‌خواند.

## تغییرها (۲۰۲۶-۱۰-۰۴)

- **قطع و وصل ریموت.** اگر ریموت دوباره باز شود و اسم دیگری بگیرد (`XBOX-2`، ...)، `Remote` خودش pipe جدید را از `Controller\remotes\*.json` پیدا می‌کند:
  اول اسم دقیق، بعد جدیدترین ریموت زنده‌ی همان کنسول. (`Remote._find_pipe`) خطای قبلی: `ریموت XBOX در دسترس نیست`.
- **OCR داخل Jupyter / پنجره‌ی Interactive در VS Code.** آنجا یک event loop از قبل در حال اجراست و خطا می‌داد:
  `Cannot run the event loop while another loop is running`. حالا در این حالت OCR روی یک thread جدا اجرا می‌شود.
  بیرون از Jupyter رفتار مثل قبل است. (`WindowsOcr.lines`)
- بعد از عوض شدن `founder.py` یک بار کرنل Jupyter را Restart کنید تا نسخه‌ی جدید بارگذاری شود.
- برای گرفتن مختصات از روی صفحه‌ی ریموت با کلید میانبر: `..\Screenshot\RemoteShot.exe` (Ctrl+Alt+S). خط `("Name", x,y,w,h)` را در کلیپ‌بورد می‌گذارد.
