# ارسال دکمه به ایکس‌باکس (xbpad)

ریموت (CPU Decode\xbrp.exe) حالا یک «هاب دسته» دارد. هر ریموت نشانی‌های خودش را در `remotes\<اسم کنسول>.json` می‌نویسد.
دکمه فقط روی کانال ورودی همان جلسه‌ی همان کنسول می‌رود، پس چند ریموت با هم قاطی نمی‌شوند.

## روش پیشنهادی: Named Pipe
- نشانی: `\.\pipe\xbrp-<اسم کنسول>` (مثلاً `\.\pipe\xbrp-XBOX`). یک خط متن بفرستید و یک خط جواب بگیرید.
- با ابزار: `xbpad.exe send -r XBOX press a`

## دستورها
| دستور | کار |
|---|---|
| `press A [ms]` | زدن و رها کردن (پیش‌فرض ۸۰ میلی‌ثانیه). چند دکمه با هم: `press lb+rb` |
| `down A` / `up A` | نگه داشتن / رها کردن |
| `stick L x y` / `stick R x y` | استیک، از ‎-1 تا 1 (y مثبت = بالا) |
| `trigger L v` / `trigger R v` | ماشه، از 0 تا 1 |
| `release` | رها کردن همه |
| `snap file.png` | ذخیره‌ی تصویر فعلی |
| `xinput N` / `xinput off` | این ریموت از دسته‌ی XInput شماره‌ی N پیروی کند |

نام دکمه‌ها: a b x y up down left right lb rb lt rt ls rs (کلیک استیک) view menu nexus (دکمه‌ی ایکس‌باکس)،
و برای حرکت کامل استیک: lsup lsdown lsleft lsright rsup rsdown rsleft rsright.

## نکته‌ها
- روی صفحه‌ی Home دکمه‌ی B بازیِ معلق را دوباره باز می‌کند. دکمه‌ی ایکس‌باکس داخل بازی منوی راهنما را باز می‌کند.
- کیبورد روی پنجره‌ی ریموت به‌طور پیش‌فرض خاموش است. برای روشن کردن، در `xbrp-settings.json` بنویسید `"keys": true`.
- روش ابری (cloud) بدون ریموت هم کار می‌کند، ولی کند است (حدود ۱.۳ ثانیه) و فقط ۱۱ دکمه دارد.
- تست‌ها: `xbpad.exe bench -r XBOX` و `xbpad.exe isolation -a XBOX -b TEST`. نتیجه‌ها در پوشه‌ی results هستند.

## استفاده در پایتون (xbox.py)
```python
import sys
sys.path.insert(0, r"C:\Users\Reach\Desktop\New Remote\Controller")
from xbox import *
setup(remote="XBOX", method="pipe")   # pipe | udp | wmcopy | tcp | keys | xinput | cloud
A(); Down(); A(500); press("lb", "rb"); stick("L", 0, 1); wait(1000)
```
برای چند کنسول هم‌زمان: `p1 = Pad("XBOX", "pipe")` و `p2 = Pad("XBOX2", "pipe")` و بعد `p1.A()` و `p2.B()`.

## کنترل ربات از پنل ریموت (۲۰۲۶-۱۰-۰۸ تا ۱۰-۰۹)
فایل `remotectl.py` کنار `xbox.py`. قبل از هر دکمه و هر `wait` خودکار:
- یک خط لاگ در پنل ریموت (انگلیسی).
- دکمه‌های پنل: Start / Pause (Resume) / Stop. «Stop» خطای `BotStopped` می‌دهد؛ اجرای دوباره‌ی سلول خودش ادامه می‌دهد.
- اگر ریموت قطع باشد: ۸ ثانیه صبر، بعد «اتصال دوباره» تا ۳ بار، نشد → `RemoteDown`.
- ریموت قدیمی که این دستورها را نمی‌شناسد: همه خاموش، مثل قبل.

تابع‌های جدید `xbox.py`:
```python
log("text")          # یک خط در لاگ پنل
wait_start()         # صبر تا «Start» پنل
bot_check()          # فقط چک: توقف / توقف موقت / سلامت ریموت
platform()           # تیک XS پنل: "Ser" یا "One"
XMenu()              # دکمه‌ی Menu دسته (اسم قبلی Menu با tkinter قاطی می‌شد)
```
- روش pipe: دستورهای کنترل روی همان اتصال دکمه‌ها می‌روند (هر برنامه ۲ اتصال). ریموت جدید هر وقت لازم باشد اتصال تازه باز می‌کند.
- جزئیات ریموت: `CPU Decode\CLAUDE.md` بخش ۱۲.

## شمارنده‌ی دکمه (۲۰۲۶-۱۰-۰۹)
`remotectl.mark_input()` با هر press / down / up / stick / trigger / release در xbox.py صدا زده می‌شود.
founder.py با `input_seq()` می‌فهمد فریمی که دارد مال قبل از دکمه است و فریم تازه می‌گیرد.
نکته: `down("a")` با d کوچک یعنی «نگه داشتن» و اسم دکمه می‌خواهد؛ دکمه‌ی پایین `Down()` است.


## قطع و وصل ریموت (۲۰۲۶-۱۰-۰۴)

اگر ریموت بسته و دوباره باز شود در حالی که برنامه‌ی پایتون هنوز اتصال قدیمی را نگه داشته، اسم قدیمی (مثلاً `xbrp-XBOX`) هنوز آزاد نیست
و ریموت جدید اسم دیگری می‌گیرد: `XBOX-2`، `XBOX-3`، ...
حالا `xbox.py` در این حالت خودش ریموت را دوباره پیدا می‌کند: اول اسم دقیق، بعد جدیدترین ریموت زنده‌ی همان کنسول در `remotes\*.json`.
فایل‌های جامانده از ریموت‌های بسته‌شده (pid مرده) نادیده گرفته می‌شوند. (توابع `_remote_info`، `_pid_alive`، `Pad._reconnect`، `Pad._control`)
در کد خودتان همان `setup(remote="XBOX")` بماند.
